## Обзор

Этот документ описывает процесс подготовки CatVRF к аудиту Роскомнадзора и ФСТЭК для проверки соответствия требованиям 152-ФЗ и Приказа ФСТЭК №21.

---

## 1. Типы проверок Роскомнадзора в 2026 году

### 1.1. Профилактические визиты

Для организаций высокого риска (крупные маркетплейсы с биометрией и миллионами субъектов):
- Фокус на высоком риске
- Проверка документации и технических мер
- Рекомендации по устранению замечаний

### 1.2. Внеплановые проверки

По следующим основаниям:
- Жалобы субъектов ПДн
- Утечки персональных данных
- Нарушения локализации данных
- Трансграничная передача без основания

### 1.3. Плановые проверки

Мораторий на плановые проверки до 2030 года, за исключением случаев высокого риска.

## 3. Пошаговая подготовка к аудиту

### Шаг 1. Подача уведомления в реестр операторов

**Срок:** До начала обработки ПДн

**Действия:**
1. Заполнить уведомление на https://pd.rkn.gov.ru/
2. Указать все категории ПДн (включая биометрические)
3. Указать цели обработки
4. Указать меры защиты (ссылка на Приказ ФСТЭК №21)
5. Получить регистрационный номер
6. Добавить номер в `.env`: `ROSKOMNADZOR_REGISTRY_NUMBER=XXX`

**Документы для подачи:**
- Уведомление (форма Роскомнадзора)
- Акт определения УЗ-3
- Политика обработки ПДн
- Приказ о назначении ответственного

### Шаг 2. Настройка технических мер

**Конфигурация:** `config/ispdn.php`

```bash
# Установить уровень защищённости
ISPDN_PROTECTION_LEVEL=3

# Настроить оператора
ISPDN_OPERATOR_NAME="CatVRF LLC"
ISPDN_OPERATOR_INN="..."
ISPDN_OPERATOR_OGRN="..."
ISPDN_OPERATOR_ADDRESS="Russia, Moscow"
ISPDN_OPERATOR_CONTACT="privacy@catvrf.ru"

# Настроить ответственного
ISPDN_RESPONSIBLE_NAME="..."
ISPDN_RESPONSIBLE_POSITION="Information Security Officer"
ISPDN_RESPONSIBLE_EMAIL="..."
```

**Проверка:**
```bash
php artisan tinker
>>> app(App\Services\Compliance\PersonalDataComplianceService::class)->checkCompliance()
```

### Шаг 6. Подготовка доказательств

**Логи ClickHouse:**
```sql
-- Получить логи за последний год
SELECT * FROM personal_data_audit 
WHERE timestamp >= now() - INTERVAL 1 YEAR 
LIMIT 10000;
```

**Записи согласий:**
```sql
-- Проверить наличие согласий на биометрию
SELECT * FROM user_consents 
WHERE consent_type LIKE 'biometric_%' 
AND status = 'granted';
```

**Акты уничтожения:**
```sql
-- Проверить уничтожение ПДн
SELECT * FROM user_consents 
WHERE status IN ('withdrawn', 'revoked') 
AND data_purged_at IS NOT NULL;
```

## 4. Типовые вопросы инспектора

### 4.1. Документы

**Вопрос:** Где ваше уведомление в реестре операторов?
**Ответ:** Регистрационный номер: [НОМЕР], ссылка: https://pd.rkn.gov.ru/

**Вопрос:** Покажите политику обработки ПДн.
**Ответ:** Доступна по адресу: https://catvrf.ru/privacy

**Вопрос:** Как вы обеспечиваете согласие на биометрические данные?
**Ответ:** Используем отдельное письменное согласие с УКЭП или письменной подписью (шаблон: `docs/compliance/152-fz/biometric_consent_form_template.md`)

### 4.2. Технические меры

**Вопрос:** Какой уровень защищённости вы используете?
**Ответ:** УЗ-3, обоснован объёмом субъектов (>100 000) и наличием биометрических данных (Акт УЗ-3: `docs/compliance/152-fz/protection_level_act_template.md`)

**Вопрос:** Как вы шифруете данные?
**Ответ:** Column-level encryption (AES-256-GCM) для чувствительных полей, TLS 1.3 для передачи, диск шифрование

**Вопрос:** Где хранятся ваши данные?
**Ответ:** Все данные локализованы на территории РФ, серверы в дата-центрах [ДАТА-ЦЕНТР]

**Вопрос:** Как вы логируете доступ к ПДн?
**Ответ:** Immutable audit логи в ClickHouse, TTL 7 лет, все операции логируются (PersonalDataAccessAudit)

### 4.3. Биометрия

**Вопрос:** Как вы получаете согласие на биометрию?
**Ответ:** Отдельное письменное согласие с УКЭП или письменной подписью, явное информирование о правах

**Вопрос:** Что происходит с биометрией при отзыве согласия?
**Ответ:** Уничтожение в течение 30 дней автоматически через PurgePersonalDataJob

**Вопрос:** Где хранятся биометрические данные?
**Ответ:** В зашифрованном виде (AES-256-GCM), отдельное хранение, доступ только по JWT токену

### 4.4. Модель угроз

**Вопрос:** У вас есть модель угроз?
**Ответ:** Да, документ: `docs/compliance/152-fz/threat_model.md`, автоматически обновляется из БДУ ФСТЭК

**Вопрос:** Как вы используете БДУ ФСТЭК?
**Ответ:** Автоматическая синхронизация через SyncFstecBduJob, фильтрация релевантных угроз, обновление risk score

## 6. Реагирование на замечания

### Критические замечания (устранить немедленно)

1. **Отсутствие уведомления в реестре**
   - Действие: Подать уведомление немедленно
   - Срок: 1 рабочий день

2. **Отсутствие согласия на биометрию**
   - Действие: Приостановить обработку биометрии, получить согласия
   - Срок: 3 рабочих дня

3. **Данные не локализованы в РФ**
   - Действие: Перенести данные в РФ
   - Срок: 30 дней

### Высокие замечания (устранить в течение 7 дней)

1. **Отсутствие шифрования**
   - Действие: Включить column-level encryption
   - Срок: 3 дня

2. **Отсутствие аудита**
   - Действие: Настроить ClickHouse логирование
   - Срок: 3 дня

3. **Неполные меры защиты**
   - Действие: Реализовать недостающие группы мер
   - Срок: 7 дней

### Средние замечания (устранить в течение 30 дней)

1. **Устаревшая документация**
   - Действие: Обновить документы
   - Срок: 7 дней

2. **Отсутствие модели угроз**
   - Действие: Создать модель угроз
   - Срок: 14 дней
