## 1. Общие положения

### 1.1. Назначение регламента

Настоящий Регламент устанавливает порядок организации и обеспечения защиты персональных данных при их обработке в информационной системе персональных данных (ИСПДн) CatVRF.

Регламент разработан в соответствии с:
- Федеральным законом от 27.07.2006 № 152-ФЗ «О персональных данных»
- Постановлением Правительства РФ № 1119 от 01.11.2012
- Приказом ФСТЭК № 21 от 18.02.2013
- Постановлением Правительства РФ № 21 от 15.02.2022

### 1.2. Область применения

Регламент обязателен для исполнения всеми сотрудниками CatVRF, имеющими доступ к персональным данным пользователей.

### 1.3. Термины и определения

- **ИСПДн** — информационная система персональных данных
- **ПДн** — персональные данные
- **УЗ-3** — уровень защищённости информации
- **НСД** — несанкционированный доступ
- **Биометрические ПДн** — персональные данные, относящиеся к физиологическим или биологическим особенностям человека

## 3. Идентификация и аутентификация

### 3.1. Требования к аутентификации

1. **Пользователи:**
   - Обязательная двухфакторная аутентификация (2FA)
   - Поддержка Passkeys (WebAuthn)
   - Поведенческая биометрия для непрерывной аутентификации

2. **Сотрудники (staff):**
   - Обязательная двухфакторная аутентификация
   - Passkeys (обязательно)
   - Поведенческая биометрия
   - JIT (Just-In-Time) доступ для чувствительных данных

### 3.2. Управление паролями

- Минимальная длина пароля: 12 символов
- Требования к сложности: заглавные, строчные, цифры, спецсимволы
- Срок действия пароля: 90 дней
- Блокировка после 5 неудачных попыток на 15 минут

### 3.3. Биометрическая аутентификация

- Face ID — при наличии отдельного письменного согласия
- Поведенческая биометрия — при наличии отдельного согласия
- Голосовая биометрия — при наличии отдельного согласия

## 4. Разграничение доступа

### 4.1. Ролевая модель

| Роль | Права доступа | JIT required |
|------|---------------|--------------|
| User | Собственные данные | Нет |
| Staff | Данные тенанта (маскированные) | Нет |
| Moderator | Данные тенанта (полные при JIT) | Да |
| Admin | Все данные (полные при JIT) | Да |
| Security Admin | Все данные + настройки | Да |

### 4.2. Принцип наименьших привилегий

Каждый сотрудник имеет минимально необходимый набор прав для выполнения своих обязанностей.

### 4.3. JIT доступ

Доступ к чувствительным данным (email, phone, INN, биометрия) для сотрудников требует JIT-разрешения:
- Запрос доступа через Filament
- Указание причины и срока
- Одобрение security admin
- Автоматический отзыв после истечения срока

---

## 5. Регистрация и учёт действий

### 5.1. Логирование

Все действия с ПДн логируются в ClickHouse:
- Доступ к данным (чтение, запись, удаление)
- Изменения согласий
- Экспорт данных
- Уничтожение данных
- Попытки НСД

### 5.2. Хранение логов

- ClickHouse: 7 лет (immutable)
- MySQL fallback: 1 год
- Резервные копии: 7 лет

### 5.3. Мониторинг

Автоматический мониторинг аномалий:
- Массовый экспорт (> 1000 записей)
- Cross-tenant доступ
- Нестандартное время доступа
- Аномальное количество запросов

## 6. Защита от НСД

### 6.1. Tenant Isolation

Каждый тенант изолирован:
- Отдельная база данных
- Global scopes на всех моделях
- TenantIsolationMiddleware
- Row-level security

### 6.2. Защита от экспорта

- ExportGuard с лимитами
- Rate limiting
- Обязательная причина для экспорта
- Логирование всех экспортов

### 6.3. Защита от инсайдеров

- InsiderThreatService
- BehavioralBiometrics для сотрудников
- Анализ паттернов доступа
- Автоматические alert'ы

---

## 7. Шифрование данных

### 7.1. Шифрование при хранении (at-rest)

- Column-level encryption для чувствительных полей
- Алгоритм: AES-256-GCM
- Ротация ключей: каждые 90 дней
- Шифрование дисков: включено

### 7.2. Шифрование при передаче (in-transit)

- TLS 1.3 для всех соединений
- HSTS включён
- mTLS для сервисных соединений

### 7.3. Зашифрованные поля

- email
- phone
- INN
- passport_number
- biometric_face_vector
- biometric_voice_template
- behavioral_profile

## 9. Уничтожение ПДн

### 9.1. Основания для уничтожения

- Отзыв согласия субъекта
- Истечение срока хранения
- Требование закона

### 9.2. Срок уничтожения

При отзыве согласия — в течение 30 дней (ст. 10, 11 152-ФЗ).

### 9.3. Процесс уничтожения

1. Отзыв согласия через ConsentEngine
2. Планирование уничтожения (через 30 дней)
3. Dispatch PurgePersonalDataJob
4. Физическое удаление данных
5. Создание акта уничтожения
6. Логирование в ClickHouse

### 9.4. Виды уничтожения

- **Биометрические данные:** полное удаление
- **Иные ПДн:** полное удаление или анонимизация
- **Заказы:** анонимизация (для налогового учёта)

## 10. Обработка биометрических данных

### 10.1. Отдельное согласие

Обработка биометрических данных требует:
- Отдельного письменного согласия
- УКЭП или письменной подписи
- Явного информирования о правах

### 10.2. Хранение

- Обязательное шифрование
- Отдельное хранение от других ПДн
- Доступ только по JWT токену

### 10.3. Уничтожение

При отзыве согласия — уничтожение в течение 30 дней.

## 12. Реагирование на инциденты

### 12.1. Классификация инцидентов

- **Критический:** утечка > 1000 субъектов
- **Высокий:** утечка 100-1000 субъектов
- **Средний:** утечка < 100 субъектов
- **Низкий:** попытка НСД (без утечки)

### 12.2. Сроки уведомления

- **Роскомнадзор:** 24-72 часа (при > 1000 субъектов)
- **Субъекты:** 72 часа
- **Внутренний:** немедленно

### 12.3. Процесс реагирования

1. Обнаружение инцидента
2. Оценка масштаба
3. Локализация инцидента
4. Уведомление ответственных
5. Уведомление Роскомнадзора (при необходимости)
6. Уведомление субъектов
7. Анализ причин
8. Внедрение корректирующих мер
